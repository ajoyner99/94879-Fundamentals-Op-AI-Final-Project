# B1 Run Log (Person A: Lauren Johnson)

All runs on 2026-09-24, same Windows laptop (official test machine). Kafka runs in Docker (`broker`, `apache/kafka`), consumer group `featurizer_group`, topic `ticks.raw` (1 partition).

**Workloads.** Baseline: `data/sample/sample_ticks.jsonl` at rate 20. Extended: `data/sample/sample_ticks_long.jsonl`, 14,076 messages, which always produce 11,750 feature rows (non-market messages are skipped).

**File names.** Recorder CSVs are `lag_<label>_<YYYYMMDD>_<HHMMSS>.csv`, where the time is when the recorder started. Featurizer logs are `featurizer_<label>.log`. Original file names are kept as-is; corrections are recorded here instead of by renaming.

**Definitions used below.**
- *Arrival / processing:* recorder's `arrival_rate_per_s` / `processing_rate_per_s`, full windows only (partial first/last windows excluded).
- *Lag at end of replay:* lag at the last sample before the replay finished.
- *Kept up:* processing matched arrival and lag stayed within the commit "bounce" (roughly < ~150). *Fell behind:* processing below arrival and lag rising across samples.
- *Seed:* `data/processed/features_drain_test_t1.parquet` (~11,750 rows). Pre-filled runs start from a fresh **copy** of it; the seed itself is never run on directly.
- *Parquet / commit %:* share of the featurizer's measured time from the last `[timing]` line (`scripts/b1_timing_breakdown.py`).

**Exclusion rule (adopted after the runs below, applies going forward):** a run is excluded if the offset reset was not done, the starting parquet had the wrong row count, the featurizer was not running as intended, or recorder sample gaps averaged over ~5 s. Excluded runs are kept and listed, not deleted.
